# C 数组容量与有效长度

这次扩展 schema 3 的数组输入：每个数组的物理容量可选 1..64，所有输入展开后
合计最多 128 个标量值；入口仍最多四个参数。支持 uint32_t/bool 数组与标量组合。
schema 1/2 继续保留原先四个初始值的限制。首次用户报告为 10/11：copy8 安全检查
通过，但等价查询超时。长度分解首次实测仍为 10/11：copy8 在 n=0..3 通过，
n=4 超时。现在改为在子查询 harness 中直接初始化常量长度，正式验收待运行。

## 输入表示

以下是 `clear16.json` 中的输入声明：

```json
{
  "a": {"type": "uint32_t[]", "length": 16, "length_field": "n"},
  "n": {"type": "uint32_t"}
}
```

- `length: 16`：实际分配并初始化的数组容量，与 C 参数 `uint32_t a[16]` 一致。
- 可选 `length_field: "n"`：有效长度来自同一个契约中声明的 uint32_t 标量输入。
  由这个显式约定产生结构约束 `n <= 16`，并与类型边界、用户 constraints 取交集。
  无符号类型提供下界 0；有效长度可为零，也可以等于容量。
- 两个数组可共用长度字段，域会同时满足两个容量界限。
- 省略 length_field 时，只有固定容量及显式用户约束；不会猜测哪个变量代表长度。
- 报告分别记录用户约束、结构约束、完整有效表达式、容量和逻辑长度对应关系。
  不把 n 的完整类型范围悄悄改写成小类型。

当前**始终观察返回值和整个物理数组**，包括有效长度之外的尾部。
这避免把尾部错误修改当成正确优化。length_field 不改变观察范围，不免除安全检查，
也不会重写程序循环。`a[n]` 在 n 等于容量时仍越界，应当失败。
每边独立初始化、无别名；不支持 malloc、任意指针、数组转发、VLA 或无界内存。
循环仍要求完整展开；容量上限是实现资源限制，不是新的证明方法。

## 搜索准备

初始值超过四个时，不再构造所有元素边界值的笛卡尔积。
改用至多 256 个确定性的稀疏样本，以及至多 24 个初始谓词；优先标量控制字段和
各数组的首尾元素。长度样本包含 0、中点、容量（仍与显式上下界和其他约束相交）。
全部符号查询仍覆盖完整声明域；样本和谓词预算只影响发现效率与完整性。
复杂的元素关系可能超出当前词汇并得到 PARTIAL/UNKNOWN。没有找到合法样本，
也不等于输入域为空；必须由求解器完成可行性检查。

## 验收内容

当 equal/different 查询超时且全域安全已通过时，工具可按契约显式的 length_field
分解证明。选择取值数最少的合适长度字段，最多 17 个子域，不进行笛卡尔积或递归
分解。copy8 对应 n=0..8，每个子域中数组元素仍是完整 uint32_t 符号值。
子域 harness 把长度初始化为该子域的常量，并保留匹配的 n==常量条件、原域约束。
覆盖查询仍使用符号长度。替换只发生在检查框架的输入声明中，两个被测程序不变。
它可能帮助后端简化循环，但不是性能保证；不减少数组元素的取值或观察范围。

求解器先证明子域覆盖原查询范围，再验证每个子域的原有完整观察断言。
所有子域通过才可合并为 PROVED；有效反例可反驳父查询，失败或超时不能冒充证明。
共享原来的总时间、查询数和保留预算；安全和展开检查不绕过，程序与契约不改写。
这是一种有限证明分解，仍需完整循环展开；不保证超时一定能解决。

每次分解保存 length-partition-*.json，记录直接尝试、覆盖查询和子域查询。
最终条件仍经过充分性及补集检查。报告可能同时出现 EXACT 与早先的 SOLVER_TIMEOUT：
诊断保留原始失败尝试，最终证明依据会标注 EXHAUSTIVE_LENGTH_PARTITION。
正式验收继续要求原来的 11/11；新本地控制测试使用脚本化求解器响应，不是正式证明。

| 案例 | 检查 |
|---|---|
| copy8 | 两个 8 元素 uint32 数组与长度组合，正向/反向复制相同前缀 |
| clear16 | 16 元素 uint32 数组，可变循环与固定循环加判断清零同一前缀 |
| empty_prefix | 有效长度为零，两种实现均不改变任何元素 |
| conditional16 | 初始全零数组，条件写入与不写入仅在 n==0 时等价 |
| tail64 | 64 元素 bool 数组；n==0 时偷偷修改尾部，只在 n!=0 时等价 |
| copybits32 | 两个 32 元素 bool 数组，无长度字段，赋值与分支写入一致 |
| empty_length | 用户要求 n>=17，但容量为16，必须报告 EMPTY_DOMAIN |
| unsafe_index | 访问 a[n]，长度等于容量仍有越界，必须保持 UNKNOWN |
| short_unwind | 展开不足不能发布证明 |
| missing-solver | 缺失求解器零查询、零原生样本，保持 UNKNOWN |
| agent-capacity | 拒绝超过容量的 seed，再认证合法条件；脚本化协议控制 |

预期条件仅在搜索后独立认证，不参与发现。此阶段是集成验收，不是盲测、
自主 agent 测量或任意大数组的可扩展性承诺。
